**현황**: TECH_SPEC §4.1 의사코드는 `os.environ["CLAUDE_CODE_SESSION_ID"]` 만 사용. Commit 12 (P0 버그 fix) 에서 stdin JSON 우선 + env fallback 으로 수정.

**작업**: TECH_SPEC §4.1 의사코드 갱신 — stdin 우선 처리 명시. on_user_prompt.py / on_session_end.py 와 일관.

#### 6. PRD §7 Risks 에 stdin/env 검증 항목 추가

**현황**: PRD §7 Risks 표에 hook payload 형식 (stdin vs env) 변동 risk 미명시.

**작업**: "Claude Code hook payload 형식 변경 (stdin → env 등)" 항목 추가. mitigation: stdin + env 둘 다 처리하도록 fallback 설계.

#### 7. README 갱신 — fix 반영

### 우선순위 ③ — 코드 follow-up (v0.3.1 또는 v0.4.0)

#### 8. lib/install.py 의 settings.local.json fallback

#### 9. Plugin manifest 동시 사용 detect

**현황**: 사용자가 plugin marketplace + cn install 둘 다 했을 때 중복 fire 가능 (codex Commit 8 MINOR 4).

**작업**: cn install 시 plugin manifest 활성 상태 detect → 경고 출력.

#### 10. CHANGELOG 의 미세 수정

**현황**: CHANGELOG v0.3.0 entry 가 v0.3.0 PR 생성 시점 작성. Commit 11 (config 자동 생성) + Commit 12 (stdin fix) 미반영.

**작업**: v0.3.0 의 "Fixed" 섹션 추가 — config 자동 생성 / stdin session_id.

#### 12. `daemon.log` 파일명 rename (v0.2.x 잔재)

**현황**: `lib/logger.py:73-77` 가 여전히 `daemon.log.YYYY-MM-DD` 이름으로 활성 로그를 작성. daemon 자체는 v0.3.0 에서 폐기됐는데 로그 파일명은 v0.2.x 흔적 그대로. 사용자/디버거 혼란 유발.

**작업**: `daemon.log` → `cn.log` (또는 `refresh.log`) 로 rename. `user_turn.log` 도 동일. `lib/logger.py` + docs 갱신. /cn:status 출력 참조 갱신.

**고려**: 기존 사용자 환경의 옛 `daemon.log.*` 파일은 그대로 둠 (cleanup 안 함, 사용자 결정). README 에 한 줄 안내만 추가.
