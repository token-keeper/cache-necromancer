# cache-necromancer v0.3.0 — 사용자 테스트 가이드

> 2026-05-16 작성. PR #12 머지 전 검증용. **약 5~10분 소요** (1분 sleep + wake 확인).

## 목적

v0.3.0 의 핵심 기능 (Stop hook + asyncRewake → cache prefix 100% hit) 이 실제 환경에서 동작하는지 확인.

검증 항목:
1. Plugin 설치 → hook 등록 → 새 chat 세션부터 적용
2. user input → 1분 sleep → 자동 wake 발생
3. wake-up turn 의 cache_read 가 turn 1 cache_creation 과 일치 (100% hit)
4. `/cn:status` 출력 정확성

## 4단계: config.toml — 자동 생성 검증 + 단축 수정

### 4-1. 자동 생성 검증 (Commit 11 의 fix)

옵션 A (marketplace install) 의 경우 자동 생성은 **첫 hook fire 시** 발생 — 이 단계에서는 아직 새 세션 시작 안 했으므로 파일 없을 수 있음.

옵션 B (`cn install`) 의 경우 install 시점에 즉시 생성됨.

```bash
# 옵션 B 였으면 이미 생성됨
ls -la ~/.cache-necromancer/config.toml

# 옵션 A 였으면 일단 5단계 (새 chat) → 6단계 ("안녕") 한 번 진행 후 다시 확인
# (PRD §3.2 의 "첫 hook fire 시 자동 생성" 약속 검증)
```

생성된 default config 확인:
```bash
cat ~/.cache-necromancer/config.toml
```

기대 출력 (default):
```toml
[general]
mode = "hybrid"
refresh_interval_minutes = 50
max_refresh_count = 10
[notify]
system_notification = true
[refresh]
hybrid_wait_seconds = 60
```

### 4-2. 단축으로 덮어쓰기 (1분 wake 검증용)

50분 sleep 으로는 검증 시간이 너무 김. 1분 sleep 으로 단축:

```bash
cat > ~/.cache-necromancer/config.toml <<'TOML'
[general]
mode = "auto"
refresh_interval_minutes = 1
max_refresh_count = 3

[notify]
system_notification = true

[refresh]
hybrid_wait_seconds = 10
TOML
```

**왜 단축?**
- 50분 → 1분: 빠른 검증
- max 10 → 3: 검증 후 비용 통제 (실수 방지)
- mode = auto: 즉시 wake (notify 는 wake 안 함, hybrid 는 추가 10초 대기)

> **검증 항목 두 가지**:
> - 4-1: PRD §3.2 의 "config.toml 자동 생성" 약속 충족 (Commit 11 fix)
> - 4-2: 단축 config 로 빠른 wake 검증

## 6단계: 1분 wake 검증

새 chat 안에서:

```
안녕
```

→ assistant 응답을 받으면 background 에서 `scripts/refresh.py` 가 1분 sleep 시작.

**약 1분 ~ 1분 30초 대기** (curl 로 가만히 있으면 됨)

→ 자동으로 새 user-role 메시지가 chat 에 나타남:
```
<task-notification><summary>Stop hook feedback</summary></task-notification>
<system-reminder>[cn:keepalive] reply 'ok' only. No tools, no analysis.</system-reminder>
```

→ assistant 가 `ok` 응답.

**성공 신호**:
- 약 1분 후 wake 발생
- assistant 가 짧게 (`ok`) 응답

**실패 신호**:
- 5분 기다려도 wake 안 옴 → 7단계 트러블슈팅

## 8단계: Cache 100% hit 검증 (선택)

진짜로 cache 가 hit 됐는지 확인 (가장 중요한 검증).

새 chat 의 jsonl 찾기:

```bash
# 최근 5분 안에 수정된 jsonl
find ~/.claude/projects -name "*.jsonl" -mmin -5 -exec ls -lt {} + | head -3
```

가장 최근 파일 열기:

```bash
# 위에서 출력된 path 로 변경
JSONL=~/.claude/projects/<your-project>/<sid>.jsonl

# 마지막 3개 assistant 응답의 cache 정보
grep '"type":"assistant"' "$JSONL" | tail -3 | python3 -c '
import json, sys
for line in sys.stdin:
    msg = json.loads(line)
    usage = msg.get("message", {}).get("usage", {})
    if usage:
        cc = usage.get("cache_creation_input_tokens", 0)
        cr = usage.get("cache_read_input_tokens", 0)
        cost = usage.get("total_cost_usd") or msg.get("costUSD", "?")
        print(f"cc={cc:,} cr={cr:,} cost={cost}")
'
```

기대값:
```
turn 1 (안녕):           cc=2X,XXX  cr=1X,XXX
turn 2 (wake → ok):      cc=143     cr=4X,XXX   ← cache 100% hit!
```

`turn 2` 의 `cr` 이 `turn 1` 의 `cc + 시스템 프롬프트` 와 거의 일치 = **fundamental fix 검증 성공**.

## 트러블슈팅

### 1분 후 wake 안 옴

1. `/cn:status` → `hook 등록` 항목 확인:
   - ❌ 미등록 → 4단계 install 다시
   - ✅ 등록인데 wake 안 옴 → 새 chat 세션 시작했는지 확인 (settings hot-reload 안 됨)

2. 터미널에서 background process 확인:
```bash
ps -ef | grep "refresh.py"
# python3 refresh.py 가 sleeping 중이면 정상 (1분 후 깨어남)
```

3. 로그 확인:
```bash
tail -20 ~/.cache-necromancer/daemon.log.$(date +%Y-%m-%d)
# refresh.py 의 wake/skip log
```

### wake 가 너무 자주 발생 (max_refresh_count 도달)

`wake/notify count: 3 / 3` 도달 → 더 이상 wake 안 함. 사용자 input 시 reset.

### `cn install` 명령이 없음

```bash
.venv/bin/pip install -e .
# 또는
which cn
```

### config.toml 에 deprecated 옵션 경고

`/cn:status` 의 `⚠️ deprecated v0.2.x config` 표시 → 폐기 옵션 무시됨, 동작에는 영향 X. 수동으로 config.toml 정리하면 사라짐.

### macOS 알림이 안 옴 (hybrid 모드)

시스템 환경설정 → 알림 → Terminal/iTerm/Script Editor 권한 확인.
