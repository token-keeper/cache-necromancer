## 진단 핵심 발견 (2026-05-15 진단 세션)

### 진짜 root cause: non-tty + 활성 sid self-resume = silent hang

`claude -p . --resume <활성_sid> --fork-session --no-session-persistence --output-format json --model claude-opus-4-7` 명령이 다음 조합에서만 silent fail:

| 실행 조건 | 결과 |
|---|---|
| **터미널 직접 + 활성 sid** (tty) | 응답 stream 정상, cache_read=268554, cleanup hang (Ctrl+C 까지) |
| **subprocess + 활성 sid** (non-tty) | **stdout/stderr 모두 0 byte, 90초+ silent hang** |
| **subprocess + 종료된 sid** (non-tty) | 8.7s 정상 종료, cache_read=18833 |

### 데몬 영향

`daemon/refresh.py:99-108` 의 `subprocess.run(cmd, capture_output=True, ...)` = 항상 non-tty + 활성 세션 fire. 따라서:
- 모든 활성 세션 fire → 240s silent timeout
- `reason=TIMEOUT` 분기 → state.next_refresh_at 갱신 못 함
- 다음 fire 도 같은 hang → 무한 timeout loop
- **사용자 입장**: cache 안 이어지는 것처럼 보임 (실은 데몬이 응답 못 받는 거)

### v0.2.2 fix 들 재평가

| fix | 평가 |
|---|---|
| 모델 명시 (transcript 추출) | ✅ tty 환경에선 작동 (cache_read=268K 직접 evidence). 데몬은 응답 자체를 못 받아 효과 안 보임 |
| timeout 120 → 240 | ❌ 응답이 안 오는 상황이라 의미 없음 |
| idle shutdown 조건 변경 | ✅ 별개 이슈, 정상 작동 |

→ **PR #11 fix 는 옳은 방향이지만 더 깊은 issue (tty 차이) 가 있어서 데몬 환경에서 효과를 못 본 것.**

## v0.2.3 (또는 v0.3.0) 트랙: root cause fix

### Fix 방향 후보

1. **데몬을 pty wrap** *(추천)* — Python `pty` 모듈로 fake tty 만들어 claude CLI 가 tty 인식
   - 장점: 한 곳 (refresh.py) fix 로 끝
   - 단점: cleanup hang 은 여전 → timeout 후 partial response 활용 필요. macOS only OK.
   - 검증: pty wrap 으로 활성 sid fire 가 응답 받으면 fix 방향 확정

2. **활성 세션 fire 포기, 별도 sid + transcript 복사** — architecture 변경
   - 장점: lock 충돌 없음, non-tty 도 정상
   - 단점: cache prefix 일치 보장 어려움, 복잡도 큼

3. **Anthropic CLI fix 요청** — `--non-interactive` flag 또는 `--fork-session` 동작 명세화
   - 장점: 정석
   - 단점: 시간 오래

### 추천 진행 순서

1. **PR #11 머지** (v0.2.2 patch — 회귀 가드 충분, 모델 명시 fix 는 옳음)
2. **새 브랜치** `feature/v0.2.3-fire-pty-wrap` 생성
3. **검증 fire**: pty wrap 코드 prototype → 활성 sid 로 fire → 응답 받는지 확인
4. **검증 통과 시**: `daemon/refresh.py:fire()` 의 subprocess.run 을 pty 기반으로 교체
5. **회귀 가드** 추가 (pty wrap 동작, cleanup hang 후 partial response 처리)
6. **PR #12 (v0.2.3)** 생성

### 파일 위치

- `daemon/refresh.py:99-108` — 현재 subprocess.run 호출. pty wrap 적용 대상
- `daemon/refresh.py:130-170` — 응답 파싱 (list/dict 처리). cleanup hang 후 partial JSON 파싱 보강 필요
- `lib/config.py:18` — `fire_timeout_seconds=240`. pty 환경에선 더 짧게 가능
