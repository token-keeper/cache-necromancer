## 다음에 할 일

### P0 — `bad_output` / `timeout` fire 폭주 디버깅 (Task #1, 가장 우선)

**증거**: v0.2.0 도그푸딩 중 `/cn:status` 의 "최근 24h fires" 박스:

```
총 31회 · bad_output=27 · timeout=4
```

→ 24시간 fire 31회 **전부 실패**. 도구의 핵심 기능 (cache TTL 갱신) 이 실사용 환경에서 작동 안 함.

**`FireReason` 분기** (`daemon/refresh.py`):
- `BAD_OUTPUT`: `claude -p` 가 응답했지만 응답 파싱 실패 / 캐시 갱신 신호 없음
- `TIMEOUT`: `fire_timeout_seconds` (기본 120) 초과

**조사 포인트**:
1. `daemon/refresh.py` 의 `build_fire_command` 가 만드는 명령이 실제 환경에서 정상 작동하는지 (예: `claude -p . --resume <sid> --fork-session --no-session-persistence --output-format json`).
2. `claude` CLI 버전 호환성 — Anthropic 이 fork-session / no-session-persistence flag 동작 변경?
3. `output-format json` 의 응답 파싱 — 어떤 필드를 보고 OK/BAD_OUTPUT 판정하는지.
4. 한 세션에 fire 가 누적될 때 token 누적으로 응답이 길어져 timeout 가능성.
5. `fire.log.YYYY-MM-DD` 에 raw stderr/stdout 기록 여부 확인. 없다면 디버그용 임시 로깅 추가.

**진행 방법**:
- `bad_output` / `timeout` 분기 detection 코드 위치 파악 (`daemon/refresh.py` 또는 fire 로 분기되는 함수)
- 실제 환경에서 manual fire 1회 trigger 후 stderr/stdout 캡쳐 (`scripts/_probe_fire.py` 같은 디버그 스크립트 신규 작성)
- 응답 형식 변경 여부 확인 → fix 적용

**예상 분량**: 큼 (조사 + fix + 회귀 가드). 별도 issue 분리 가능.

### P1 — `cwd` 마스킹 정책 결정 (Task #2)

**배경**: codex 가 2회 PR 리뷰에서 지적 — `cwd` 가 `/cn:status` 출력 + state file 에 전체 경로 노출됨. 회사 프로젝트 / 클라이언트 디렉토리 명 노출 가능성. 단 false positive 위험 (mask 후엔 정리 시 sid 매핑 어려움) 으로 미루어왔음.

**옵션**:
- A) **그대로 유지** — 사용자가 자기 화면만 보므로 위험 작음. 현재 정책.
- B) **`~/` prefix 자동 치환** — `$HOME` 부분만 `~/` 로 단축. 화면 노출 감소 + 비용 0. 추천.
- C) **전체 마스킹** — 정리 시 sid 매핑 어려움. 비추천.

**결정 시점**: 사용자 정책 입력 받기. B) 가 합리적이라면 작은 fix.

### P2 — multi-session 자동 정리 옵션 (Task #3, 선택)

**배경**: README 트러블슈팅에 "다른 프로젝트 세션 자동 추적" 설명 + manual 정리 방법 (pkill + rm state) 안내. 자동 정리 옵션 추가 고려.

**옵션**:
- 새 명령 `/cn:cleanup` — disabled 세션 + 24h 비활성 세션 자동 제거
- `~/.cache-necromancer/config.toml` 에 `[advanced] auto_cleanup_disabled_after_days = 7` 등
- README 권장 패턴만 보완

**우선순위 낮음** — 사용자 manual cleanup 으로 충분 가능.

### P3 — 데몬 `started` ISO 정규화 (Task #4, cosmetic)

**현상**: `/cn:status` 의 데몬 박스 `시작 2026년 5월 14일 목요일 07시 49분 07초` — 한글 long format. ISO 형식 (`2026-05-14T07:49:07+00:00`) 으로 정규화하면 일관성.

**파일**: `daemon/lockfile.py` 의 spawn 메타 저장 부분 (`Mon May 12 13:00:00 2026` 류 출력 위치). 또는 `cn_status.py` 의 데몬 박스에서 display 시점에 변환.

**예상 분량**: 작음 (한 줄 fix + 테스트).

## 도메인 정보

**개요**: cache-necromancer 는 Claude Code 의 1시간 프롬프트 캐시 TTL 을 헤드레스 CLI (`claude -p --resume`) 로 자동 갱신하는 macOS 플러그인. PRD: `docs/superpowers/specs/archive/2026/Q2/2026-05-12-cache-necromancer-PRD.md`, TECH_SPEC: `docs/superpowers/specs/archive/2026/Q2/2026-05-12-cache-necromancer-design-v5.md`.

**핵심 컨벤션**:
- Python 3.11+, pytest + freezegun. 의존성 `uv sync --extra dev`.
- 테스트 실행: `.venv/bin/python -m pytest --tb=short`.
- 커밋 메시지: `feat:` / `fix:` / `test:` / `docs:` / `chore:` 접두사 + 한글 본문. Co-author: `Co-Authored-By: Claude Opus 4.7 <noreply@anthropic.com>`.
- 디버깅 로그 접두사: `BRODY_` (글로벌 CLAUDE.md 룰).

**함정**:
- `commands/*.md` 변경 후 `/reload-plugins` 권장 (directory 마켓플레이스 캐시 갱신).
- `hooks/hooks.json` 변경 시 데몬 자체는 그대로지만 hook 로드는 reload 필요.
- 데몬은 시작 시 1회만 `load_config()`. config.toml 일부 키 (`mode`, `max_refresh_count`, `imminent_threshold_minutes`) 변경 시 데몬 재시작 필요 (`pkill -f "python.*-m daemon"` + `rm ~/.cache-necromancer/daemon.lock`).
- v0.2.0 의 `last_user_prompt_excerpt` 는 80자 truncate + slash command skip. 디버깅 시 state 파일에서 직접 확인 가능 (`cat ~/.cache-necromancer/state/<sid>.json`).
- `tests/lib/conftest.py` 의 autouse fixture 가 `CLAUDE_PLUGIN_OPTION_MODE` 환경변수를 매 테스트 시작 시 delenv.
