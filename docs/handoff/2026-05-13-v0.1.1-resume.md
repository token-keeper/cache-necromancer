### 1. `/cn:config` 인터랙티브 setter 구현 (PR #8 안에 추가)

`commands/cn:config.md` 를 instructions 기반으로 재작성하고 `scripts/cn_config.py` 는 삭제한다.

**새 `commands/cn:config.md` 구조**:

```markdown
---
description: cache-necromancer 설정 변경 (인터랙티브)
allowed-tools: AskUserQuestion, Read, Edit, Bash
---

먼저 `~/.cache-necromancer/config.toml` 을 Read 로 읽어 현재 설정을 사용자에게 표시.

그 다음 AskUserQuestion 으로 다음을 묻는다 (단일 질문 multiSelect=false):

질문 1: "어떤 설정을 변경할까요?"
옵션:
- 변경 안 함 (현재 설정만 확인)
- mode 변경
- refresh_interval_minutes 변경
- 둘 다 변경

답에 따라 분기:
- "변경 안 함" → 종료
- "mode 변경" → 두 번째 질문 "mode 를 무엇으로 변경할까요?"
  - notify (알림만, fire 없음)
  - auto (자동 fire)
  - hybrid (60초 사전 알림 후 fire, 취소 가능)
- "refresh_interval_minutes 변경" → 세 번째 질문 "refresh_interval 을 몇 분으로?"
  - 5 (테스트용)
  - 30
  - 55 (기본값)
  - 120

변경 선택이 있으면:
1. ~/.cache-necromancer/config.toml 을 Edit 로 해당 키만 갱신
2. 데몬 재시작: `pkill -f "python.*-m daemon" 2>/dev/null; rm -f ~/.cache-necromancer/daemon.lock`
3. "✓ 설정 변경 완료. 다음 응답 시 새 mode 적용됨" 보고
```

**참고 예시**: `openai-codex` 플러그인의 `/Users/i_brody/.claude/plugins/cache/openai-codex/codex/1.0.4/commands/adversarial-review.md` — `allowed-tools: ..., AskUserQuestion` 패턴 사용.

**삭제할 파일**: `scripts/cn_config.py` (백엔드 Python 불필요), `tests/scripts/test_cn_config.py` (대응 테스트).

**테스트**: 인터랙티브 명령은 단위 테스트 어려움. `commands/cn:config.md` 가 valid markdown 인지만 검증. 실제 검증은 사용자 도그푸딩.

**Commit 메시지**: `feat(ux): /cn:config 인터랙티브 setter (AskUserQuestion 기반)`
