## 다음에 할 일

### A. `/cn:dry-run` 제거 + `/cn:status` 통합 (핵심)

#### 동기 (v0.1.x 도그푸딩에서 발견된 안티패턴)

- `/cn:dry-run` 네이밍 자체가 모호 — 일반 컨벤션상 dry-run 은 "실행 시뮬레이션" 이지만 cache-necromancer 의 dry-run 은 단순 "next fire 시점 출력".
- `/cn:status` 와 `/cn:dry-run` 정보 60-70% 겹침. dry-run 의 유일 정보는 `command:` 라인 + `cwd:` 라인.
- 명령 수가 늘어날수록 사용자 mental model 부담.

#### 작업 항목

1. **`commands/cn:dry-run.md` 삭제** + `scripts/cn_dry_run.py` 삭제 + `tests/scripts/test_cn_dry_run.py` 삭제
2. **`scripts/cn_status.py` 확장** — dry-run 정보 흡수:
   - 다음 fire 시점 시뮬레이션 (`command:` argv, `cwd:` 경로) 추가
   - 기존 출력 (데몬 / 세션 / disabled / 최근 fire 통계) 유지
3. **출력 디자인 개선**:
   - 섹션 분리: 데몬 / 세션(`(this)` 표시) / 다음 fire / 최근 fire 통계 / disabled
   - 컴팩트한 박스 또는 그룹 헤딩, 적절한 들여쓰기
   - 디자인 시안은 작업 세션에서 결정 (**사용자 도그푸딩으로 확인**)
4. **`.claude-plugin/plugin.json` 갱신** — `cn:dry-run` 명령 등록 제거 (등록 형태인지 확인 필요. directory 마켓플레이스라 자동 인식일 수도)
5. **README + CHANGELOG 갱신** — v0.2.0 breaking change 명시:
   - "Removed: `/cn:dry-run` (merged into `/cn:status`)"
   - "Changed: `/cn:status` now shows next fire simulation"
6. **version bump** — `pyproject.toml` + `.claude-plugin/plugin.json` 의 `0.1.1` → `0.2.0`
7. **회귀 테스트** — pytest 베이스라인 갱신 (cn_dry_run 7개 빠지고 cn_status 테스트 확장)

### B1. README 트러블슈팅 추가

다중 세션 자동 추적이 사용자에게 놀라움 (예: `vdit-ios-sdk`, `vdit-ios` 등 다른 프로젝트 세션이 자동 등록). PRD 의도이지만 비용 인지 필요.

- "다른 프로젝트 세션이 자동 추적되는 이유" 설명
- 정리 방법: `pkill -f "python.*-m daemon"` + state 파일 정리 / 또는 plugin disable
- 비용 인지 안내 (세션 수 × refresh_interval 만큼 fire 발생)

### B2. `scripts/cn_status.py:67` `is_current` 변수 추출 롤백 검토

이전 세션 review 에서 인접 코드 손댐 borderline 으로 flag 됨 (v0.1.1 fix-up 에선 보류). 변경 자체는 가독성 개선이지만 변경 범위 원칙 ("사용자 요청에 직접 추적 가능한 라인") 위반 가능성. 작업 세션에서 `git blame` 으로 origin 확인 후 결정.

A 작업 안에서 자연스럽게 같이 정리될 가능성 (cn_status.py 대규모 변경) — 그 경우 별도 commit 으로 분리하여 reviewable 하게.
