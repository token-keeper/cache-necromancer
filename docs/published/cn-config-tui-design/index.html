⚙️ /cn:config → 터미널 TUI 전환

cache-necromancer v0.7.0 설계 · 2026-06-24 · grill-me 8문답으로 구체화

한 줄 결론
설정 변경을 Claude 와의 대화에서 터미널 TUI 로 옮긴다. 목표는 LLM turn 0 + context 0 — 설정 작업이 대화 맥락(context window)을 전혀 차지하지 않게.

🧠 먼저, 핵심 개념: turn ≠ context

이 기획 전체가 이 한 가지에서 출발했다. 헷갈리기 쉬운데, 둘은 완전히 다른 것이다.

개념뜻
LLM turn모델(Claude)이 추론을 한 번 도는 것
context 점유그 입력·출력이 대화 기록(transcript)에 남아, 이후 모든 턴의 입력 토큰에 누적되는 것
👉 turn 이 0 이어도 context 는 먹을 수 있다.
모델이 안 돌아도, 명령과 그 결과가 대화 기록에 남으면 — 이후 모든 턴이 그 토큰을 계속 짊어진다.

😩 통증 — 지금 /cn:config 는 왜 무거운가

/cn:config 는 사실 인터랙티브 LLM 명령이다:

allowed-tools: AskUserQuestion, Read, Edit, Write

설정 하나 바꾸는데 이런 일이 벌어진다:

1Claude(모델)가 config.toml 을 Read
2AskUserQuestion 으로 질문 4개를 던지고 — 사용자 선택을 받음 (대화 왕복)
3답을 받아 Edit 으로 저장

매 단계가 모델을 거친다 → 느리고, 질문·답변·도구호출이 전부 transcript 에 쌓여 context 를 먹는다.

명령LLM turncontext비고
/cn:set0약간hook 처리 (모델 안 거침). suppressOutput 으로 0 가능 — 별도 과제
/cn:config多多AskUserQuestion 대화 → 이번 설계가 겨냥하는 진짜 통증

즉 /cn:set 은 이미 빠르다. 무거운 건 /cn:config 의 인터랙티브 대화다.

💡 해법 — TUI 가 config 를 직접 편집

설정을 터미널 TUI(cn_config.py)가 담당한다. Claude(모델)를 전혀 거치지 않는다.

❌ Before — LLM 대화

사용자 → 모델 Read → 질문4개 왕복 → 모델 Edit

turn 多 · context 多 · 느림

✅ After — 터미널 TUI

사용자 → 터미널서 cn_config.py → config.toml 직접 저장

turn 0 · context 0 · 즉시

통증의 근원은 "인터랙티브" 가 아니라 "LLM 대화" 였다. 그래서 고르는 UX 는 그대로 두고, 모델만 들어낸다.

설정 경로에서 모델(Claude)을 완전히 빼낸다

🧩 이식 가이드 — 다른 플러그인으로

이 TUI 의 설정 항목은 데이터(SCHEMA)로 선언한다. 엔진은 그 데이터만 보고 메뉴를 그린다.

SCHEMA = [
    {"key": ["wake", "arm"], "label": "소생 방식",
     "type": "choice",
     "options": [("manual", "..."), ("always", "...")]},
    {"key": ["notify", "enabled"], "label": "알림", "type": "bool"},
    # ...
]
이식은 2가지만 바꾸면 끝:
1cn_config.py 파일 복사
2SCHEMA 배열을 그 플러그인 설정으로 교체 + config 경로 1줄 수정

엔진(렌더·선택·라인보존 쓰기)은 그대로. 의존성 0(stdlib)이라 복붙 즉시 동작.
